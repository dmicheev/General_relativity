# 02. Физика кабины и два кадра наблюдателя

**ID:** T02
**Зависимости:** T01
**Артефакты:** `systems/physics.rs`, `systems/frame_bridge.rs`, `resources.rs`
**Сложность:** высокая
**Оценка:** 2–3 дня

## 1. Цель

Показать, что режимы `Planet` и `Rocket` **физически неразличимы внутри кабины**,
а `FreeFall` и `Inertial` неразличимы тоже.

Дополнительно: показать ту же картину глазами внешнего наблюдателя.

## 2. Ключевое архитектурное решение

> **Не двигать кабину. Двигать гравитацию.**

Вместо кинематического перемещения коллайдеров лифта мы:

1. Держим кабину **неподвижной** в системе лифта.
2. Выставляем `RapierContext.gravity = (0, g_eff, 0)`.
3. Внешний кадр восстанавливаем аналитически через `D(t)`.

### Почему это правильно

| Подход | Проблемы |
|---|---|
| Кинематический лифт едет вверх | Контактовое трение толкает тела; нужен ручной перенос импульсов; трудно детерминированно переключать режимы |
| **Гравитация в кадре лифта** | Тела и пол в одном кадре; контактный решатель работает штатно; переключение режима = одна запись |

Второй подход — это буквально то, что утверждает принцип эквивалентности.

## 3. Спецификация

### 3.1. Ресурсы

```rust
#[derive(Resource)]
pub struct SimConfig {

    pub view: ViewFrame,

#[derive(Resource)]

#[derive(Resource)]
pub struct BallTrace {
    // история p_lift и p_external для отладочных линий
    pub samples: Vec<[f64; 3]>,
}
```

### 3.2. Тела

| Объект | Тип | Масса | Радиус | Цвет |
|---|---|---:|---:|---|
| Ball A | Dynamic | 1 кг | 0.15 | голубой |
| Ball B | Dynamic | 5 кг | 0.15 | зелёный |
| Ball C | Dynamic | 10 кг | 0.15 | оранжевый |

**Радиус одинаковый намеренно:** различие в поведении нельзя списать на размер.

Начальные позиции: `x ∈ {−0.8, 0, 0.8}`, `y = 2.2`, `z = 0`.
Начальная скорость: ноль.
`linvel_damping = 0`, `angular_damping = 0`, `ccd = true`.

Кабина: статические коллайдеры пола, трёх стен и потолка.

### 3.3. Синхронизация гравитации

Система `sync_gravity` выполняется **до** шага физики:

```text
frame = Mode::params(sim_config.mode)   // или Custom из слайдеров
ctx.gravity = Vec3::new(0, frame.g_eff() as f32, 0)
```

При `Mode::Custom` значения берутся из ресурса `CustomParams`.

### 3.4. Переключение режима

Два разных действия, не одно:

| Действие | Клавиша | Семантика |
|---|---|---|
| `Сменить режим + сброс` | `1` `2` `3` `4` | `clock.reset()`, телепортировать тела в начальные позиции, обнулить скорости |
| `Сменить на лету` | `Shift + 1..4` | Сохранить позиции и скорости, сменить только `g_eff` |

**Почему два:** переключение на лету — это контрфактический мысленный эксперимент,
а не непрерывная физическая история. UI должен это явно подписывать.

### 3.5. FrameBridge — отображение внешнего кадра

Сцена организуется как один корень:

```
SceneRoot (Transform)
├── Cabin
├── BallA
├── BallB
├── BallC
└── (позже: Scales, PhotonTrail)
```

Каждый кадр:

```rust
let d = frame.displacement(clock.t) as f32;

match sim_config.view {
    ViewFrame::Lift => {
        scene_root.translation = Vec3::ZERO;
        camera.translation = LIFT_CAMERA_POSE;
    }
    ViewFrame::External => {
        scene_root.translation = Vec3::new(0.0, d, 0.0);
        camera.translation = EXTERNAL_CAMERA_POSE; // фиксированный
    }
}
```

**Почему это работает:**

В режиме `Rocket` тело в кадре лифта падает:
`p_lift = y₀ − ½g·t²`.
Прибавляем `D = +½g·t²`:
`p_external = y₀` — **тело стоит на месте во внешнем кадре**,
а пол кабины поднимается к нему. Это ровно то, что должно происходить.

### 3.6. Внешняя камера

- Фиксированная позиция, смотрит на область `y ∈ [−1, 5]`
- Инерциальная reference-сетка на `y = 0`, **не** является дочерней `SceneRoot`
- Авто-пауза на `t = 1.2 с` в внешнем режиме (иначе кабина улетит)
- Кнопка «Шаг назад / перезапуск»

### 3.7. Трейлы

Для каждого тела хранить последние 120 позиций в обоих кадрах.

| Режим | Трейл в кадре лифта | Трейл во внешнем кадре |
|---|---|---|
| Planet | вниз, парабола | вниз, парабола |
| Rocket | вниз, парабола | **горизонтальная прямая** |
| FreeFall | **горизонтальная прямая** | вниз, парабола |
| Inertial | горизонтальная прямая | горизонтальная прямая |

Это самый наглядный элемент всего приложения.

## 6. Типичные ловушки

| Ловушка | Симптом | Решение |
|---|---|---|
| Гравитация обновляется после шага Rapier | один кадр запаздывания, асимметрия A/B | `before(RapierSystemSet::Step)` или эквивалент |
| Тела спавнятся с `Transform`, но Rapier не подхватил | мячи падают «из другой точки» | вызывать спавн в `Update`, дать один кадр на синхронизацию |
| `SceneRoot` двигается, а камера — нет | в внешнем режиме всё улетает | двигать корень ИЛИ камеру, согласно §3.5 |
| Демпфирование включено по умолчанию | лёгкий мяч отстаёт | явно обнулить damping |
| `t` берётся из `Time::delta_seconds()` | недетерминизм | использовать только `ExperimentClock.t` |
| Смена режима без сброса скоростей | «физика сломалась» | два отдельных действия, §3.4 |
