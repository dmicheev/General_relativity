# 03. Пружинные весы: измеримое доказательство эквивалентности

**ID:** T03
**Зависимости:** T02
**Артефакты:** `scales/mod.rs`, `scales/mesh.rs`, `scales/reading.rs`
**Сложность:** средняя
**Оценка:** 1–2 дня

## 1. Цель

Траектории мячей убеждают ум. **Весы убеждают глаза.**

Нужен прибор, который в режимах `Planet` и `Rocket` показывает одинаковое число,
а в `FreeFall` и `Inertial` — ноль.

## 2. Почему это не тривиально

Наивная реализация `N = m * |g_eff|` — **тавтология**.
Мы тогда просто рисуем входной параметр, а не измеряем физику.

Весы должны получать силу **из контактного решателя Rapier**.
Только так демонстрация является экспериментом, а не иллюстрацией формулы.

## 3. Спецификация

### 3.1. Состав весов

Каждые весы — отдельная сущность-группа:

```
ScaleRoot (x = -0.8 / 0 / +0.8, y = 0, z = 0)
├── Base       — стационарная платформа, статический коллайдер
├── Spring     — визуальная пружина (helix mesh), масштабируется по Y
├── Pan        — чаша, Dynamic или Kinematic с коллайдером
└── Load       — груз (те же три массы: 1 / 5 / 10 кг)
```

**Вариант реализации чаши:**
- Простой: чаша — часть статического основания, груз лежит прямо на ней.
  Пружинаpurely visual, сжатие вычисляется из `ContactForceEvent`.
- Продвинутый: чаша на пружинно-демпферной подвеске, реализованной
  как приложенная сила в `FixedUpdate`.

**MVP требует простой вариант.** Продвинутый — stretch goal.

### 3.2. Измерение силы

Приоритет способов:

1. **`ContactForceEvent`** из Rapier (если доступен в зафиксированной версии).
   Событие содержит суммарную силу контакта за шаг.
   필요한: включить `ContactForceEventThresholds` / эквивалентный фильтр
   и подписаться на очередь событий.

2. **Fallback: измерение по проникновению.**
   Если событий нет — использовать максимальную глубину проникновения
   контакта и жёсткость контактной модели:
   `N ≈ k_contact · penetration`.
   **Обязательно** пометить в UI: «оценка, не прямое измерение».

3. **Запрещено:** вычислять `N = m * g_eff` как основной путь.
   Допустимо только как эталон для теста.

### 3.4. Визуальное сжатие

Настоящая жёсткость пружины дала бы невидимое сжатие:

```
k = 2000 Н/м, N = 9.81 Н  →  Δx = 4.9 мм
```

Поэтому используется **педагогическое отображение**:

```
compression = clamp(N / N_fullscale, 0, 1)
N_fullscale = 150 Н
visual_height = H₀ · (1 − 0.65 · compression)
```

| Масса | N в режиме A/B | compression | Визуальное сжатие |
|---:|---:|---:|---:|
| 1 кг | 9.81 Н | 0.065 | 4.2% |
| 5 кг | 49.05 Н | 0.327 | 21.3% |
| 10 кг | 98.10 Н | 0.654 | 42.5% |

**Требование:** в UI прямо подписать
«Шкала усилена для наглядности; отношение показаний линейно и честно».

### 3.5. Геометрия пружины

Сгенерировать helix mesh один раз:

```
turns = 6
radius = 0.09
wire_radius = 0.012
samples_per_turn = 24
height = 1.0   // единичная высота
```

Параметризация:

```
θ = 2π · turns · u
center(u) = (r·cos θ, height·u, r·sin θ)
```

Для каждого сечения — окружность радиуса `wire_radius` в плоскости,
перпендикулярной касательной. Соединить треугольной лентой.

Дальше **только** `Transform::scale.y = visual_height`.

> Известный артефакт: при scale по Y толщина проволоки тоже меняется.
> Для MVP это допустимо. Исправление через vertex-shader — на T07.

### 3.6. Цветовая индикация

```
N = 0        → серый / голубой («невесомость»)
0 < N < 0.5  → зелёный
0.5..0.85    → жёлтый
> 0.85       → красный
```

Интерполяция `StandardMaterial::base_color` по `compression`.

### 3.7. Сброс и «бросок»

- `R` — сброс: грузы поднимаются на `y = 1.8` и отпускаются над чашами.
- В `Planet` / `Rocket` они падают, ударяются, пружина проседает с перелётом,
  затем стабилизируется.
- В `FreeFall` / `Inertial` грузы **остаются висеть** на уровне 1.8 м.

Перелёт при ударе — важная деталь: она показывает, что прибор
реагирует на динамическую силу, а не рисует константу.

- [x] В `FreeFall` и `Inertial` показания `< 0.05` Н в установившемся режиме *(тест `t03_2_3`)*
- [x] Показания линейны по массе *(тест `t03_4_5`)*

## 6. Типичные ловушки

| Ловушка | Решение |
|---|---|
| Сила суммируется за несколько кадров | читать и обнулять очередь событий каждый fixed step |
| События не приходят | проверить, включён ли event threshold / filter в плагине |
| Сжатие «прыгает» | сглаживание: `compression = lerp(old, new, 0.2)` |
| Груз проваливается через чашу | включить CCD, уменьшить dt, проверить коллайдеры |
| Весы показывают `m·g_eff` всегда | **архитектурная ошибка**, см. §2 |
| Пружина растёт из центра, а не от базы |.setParent / сместить геометрию так, чтобы основание было в y=0 |

### Handoff → T04 (фактический, T03 закрыт)

- **`ScaleReadings`** — ресурс `resources.rs`, заполняется в
  `scales/reading.rs` раз за кадр (Update); элементы `lift_core::ScaleReading`;
  заморозка на паузе через гейт `SimSteps`.
- **SceneRoot** — визуальный корень, entity в ресурсе `SceneRootRef`
  (спавн в `scene::setup_scene`). Дети: кабина, меши грузов
  (`BallVisual`), стойки весов (`SpringVisual` + колонна/чаша).
  Физика — в корне мира (см. 00-physics-spec, T02 п. 1).
- **Нестандартная геометрия**: `scales/mesh.rs::helix_mesh(HelixParams)`
  → `Mesh` (TriangleList, позиции+нормали+индексы) → `meshes.add(...)`.
  Пример живого масштабирования — `update_scale_visuals` (только
  `Transform.scale.y`).
- **Цвет по данным**: `compression_color(c)` + правка
  `StandardMaterial.base_color` через `Assets<StandardMaterial>`
  из `MeshMaterial3d` (пример в том же `update_scale_visuals`).
- **События Rapier**: `ActiveEvents::CONTACT_FORCE_EVENTS` +
  `ContactForceEventThreshold(0.0)` на коллайдере; чтение
  `MessageReader<ContactForceEvent>` (ресурс зарегистрирован плагином).
  Для фотона (T04) контактных событий нет — там аналитика lift-core.
