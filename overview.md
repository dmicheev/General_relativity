# Лифт Эйнштейна

Интерактивное 3D-приложение для понимания **принципа эквивалентности** —
физического моста от специальной теории относительности к общей.

## 0. Общее описание проекта (копировать в начало каждой сессии)

```text
ПРОЕКТ: «Лифт Эйнштейна» — интерактивное 3D-приложение (браузер, WASM),
демонстрирующее принцип эквивалентности ОТО: наблюдатель в закрытой кабине
не может локально отличить покой на планете, ускорение в пустоте и свободное
падение. Мячи, пружинные весы и луч света ведут себя одинаково в первых двух
режимах и «невесомы» в третьем.

СТЕК: Rust → wasm32-unknown-unknown, Trunk, Bevy (WebGPU/WebGL2 fallback),
bevy_rapier3d (твёрдые тела), bevy_egui (учебный UI). Версии bevy /
bevy_rapier3d / bevy_egui фиксируются совместимой тройкой на этапе 1
(см. 00-physics-spec.md, раздел «Зафиксированный стек») — не из памяти.

СТРУКТУРА: cargo workspace из двух crate:
- lift-core — чистый Rust, f64, без Bevy/Rapier/wasm-bindgen.
  Вся физика и математика: FrameParams, Mode (Planet/Rocket/FreeFall/
  Inertial/Custom), g_eff = −g_ext − a_lift, аналитические траектории,
  фотон (external → lift), детерминированный fixed-step, unit-тесты.
- lift-app — Bevy + Rapier + egui, только адаптация: спавн, рендер,
  ввод, f64 → Vec3. Компилируется в WASM.

ГЛАВНЫЙ ИНВАРИАНТ: симуляция всегда в системе лифта.
p_external(t) = p_lift(t) + D(t),  D(t) = ½·a_lift·t².
Внешний вид — отображение, а не вторая симуляция.
Весы: сила из контактного решателя Rapier, не из формулы m·g_eff.
Фотон: аналитика из lift-core, Rapier для света НЕ используется.

ЭТАПЫ (файлы этапов лежат в корне репозитория, каждый закрыт
только после «Критериев приёмки»):
00-physics-spec → 01-foundation (WASM-сцена) → 02-lift-physics (4 режима,
2 кадра) → 03-scales → 04-light → 05-performance (размер бандла) →
06-ui-pedagogy (предсказания) → 07-shaders-release (шейдеры, CI, деплой).

КОМАНДЫ:
- cargo test -p lift-core        # тесты ядра нативно
- trunk serve --open             # веб-разработка
- trunk build --release          # релиз

ВНЕ MVP: численный решатель уравнений Эйнштейна, чёрные дыры, линзирование,
замедление времени, приливные силы, вращение/Кориолис. Моделируется только
однородное поле в малой области — ровно там, где справедлив принцип
эквивалентности.

ПРАВИЛА ДЛЯ ИИ — см. раздел 9 ниже (соблюдать всегда).
```

## 1. Идея одним абзацем

Наблюдатель закрыт в кабине без окон. Он не может никаким локальным экспериментом
отличить три ситуации:

- кабина стоит на планете;
- кабина ускоряется в пустом пространстве;
- кабина свободно падает в гравитационном поле.

Приложение делает это различие (вернее, его отсутствие) **видимым**:
мячи, пружинные весы и луч света ведут себя одинаково в первых двух случаях
 и становятся «невесомыми» в третьем.

## 2. Что находится за рамками MVP

| Не делаем в MVP | Почему |
|---|---|
| Полный численный решатель уравнений Эйнштейна | Не нужен для принципа эквивалентности |
| Черные дыры, горизонт событий, аккреционные диски | Другой учебный модуль |
| Гравитационное линзирование массой | Требует кривизны, а не только ускорения |
| Замедление времени / двойные часы | Отдельный модуль СТО/ОТО |
| Приливные силы | Нарушают локальность; отдельный продвинутый модуль |
| Вращение, сила Кориолиса, прецессия Томаса | Отдельный модуль неинерциальных систем |

**Честная формулировка для пользователя:**
«Мы моделируем однородное поле в малой области пространства-времени.
Это ровно та область, где справедлив принцип эквивалентности».

### Почему два crate

`lift-core` не зависит от Bevy, Rapier и `wasm-bindgen`.
Это позволяет:

- гонять unit-тесты **нативно за毫秒**, без браузера;
- проверять физику аналитикой;
- переиспользовать ядро в CLI, нативном приложении или серверной симуляции;
- не чинить математику каждый раз, когда Bevy меняет API.

### Главный инвариант координат

```text
p_external(t) = p_lift(t) + D(t)
D(t) = ½ · a_lift · t²
```

Симуляция **всегда** идёт в системе лифта.
Внешний вид — это отображение, а не вторая симуляция.

## 6. Версионный контракт

Никто не знает заранее, какая связка версий совместима **сегодня**.

Поэтому на этапе 1:

1. Проверить актуальные версии `bevy`, `bevy_rapier3d`, `bevy_egui` на docs.rs / crates.io.
2. Найти официально совместимую тройку (см. README плагинов, не номера по памяти).
3. Записать её в `Cargo.toml` и закоммитить `Cargo.lock`.
4. Внести фактические версии в `00-physics-spec.md`, раздел «Зафиксированный стек».

**Запрещено** подключать версии разных поколений API «потому что цифры красивые».
Если совместимой тройки нет — этап 1 считается проваленным и выбирается
более старая согласованная связка.

## 8. Глоссарий

| Термин | Значение в проекте |
|---|---|
| `g_ext` | Величина внешнего однородного гравитационного ускорения, м/с² |
| `a_lift` | Знаковое ускорение кабины вдоль +Y во внешнем кадре, м/с² |
| `g_eff` | Эффективное ускорение в кабине: `−g_ext − a_lift` |
| `D(t)` | Смещение кабины во внешнем кадре: `½·a_lift·t²` |
| `c_vis` | Визуальная скорость света (замедленная для наглядности), м/с |
| Кадр лифта | Система отсчёта, в которой кабина покоится |
| Внешний кадр | Система отсчёта, не ускоренная вместе с кабиной |
